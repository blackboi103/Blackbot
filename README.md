# BlackBot

Personal AI assistant and automation system.

## Current Stage

Development environment and project setup.

## Project Purpose

OpenClaw is a precursor and learning project for Blackbot.

The purpose of OpenClaw is to provide a practical environment for learning how to
design, build, secure, and operate an advanced AI agent.

OpenClaw is not intended to remain the permanent primary assistant.

The knowledge, architecture lessons, integrations, security practices, and
development experience gained from OpenClaw will be documented and eventually
used to build Blackbot.

## Long-Term Goal: Blackbot

Blackbot is the eventual primary local AI agent.

Blackbot is intended to run locally using Hermes + Ollama, with privacy,
local control, and extensibility as major design goals.

Blackbot will eventually incorporate the capabilities developed and learned
through OpenClaw, including:

- General AI assistance
- Persistent memory
- Obsidian integration
- File management
- Email
- Calendar
- FIU/Canvas integration
- Task and project management
- Budgeting
- Automation
- Tool use
- Web access where appropriate
- Agent orchestration

Blackbot will additionally have a specialized trading capability, which
OpenClaw does not need to implement.

Trading development will progress through:

1. Research
2. Backtesting
3. Simulation
4. Paper trading
5. Controlled validation
6. Explicitly authorized live trading, if ever enabled

Live trading must never be enabled automatically.

## Knowledge Transfer

OpenClaw will document important development knowledge in Obsidian.

Documentation should capture:

- Architecture decisions
- Development lessons
- Security lessons
- Integration knowledge
- Problems and solutions
- Failed approaches
- Deprecated approaches
- Future improvements
- Lessons applicable to Blackbot

The goal is:

OpenClaw → Obsidian knowledge → Blackbot

Blackbot should be able to learn from the documented experience of building
OpenClaw rather than starting from zero.

## Development Philosophy

OpenClaw is also a learning environment for the developer.

Development should prioritize understanding over simply completing tasks.

For major components, documentation should explain:

- What is being built
- Why it is needed
- How it works
- Security considerations
- What was learned
- How the concept could transfer to Blackbot
